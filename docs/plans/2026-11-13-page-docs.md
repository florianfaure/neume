# La page Docs — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** mettre en ligne `/docs` sur neume.dev, tirer de la page le nouveau README, et générer et contrôler le zip des SVG à 24 px.

**Architecture :**
- La maquette validée (`site/app/docs/docs.tsx`, branche `docs-page`) devient la page.
- La barre, le pied de page, la palette ⌘K et la fiche d'icône sortent de `app/_home/home.tsx` dans `site/app/_shell/`, partagés par les deux pages.
- Le zip est un fichier généré de la racine, comme `packages/*/dist`. `scripts/generate.mjs` le produit en mémoire, `build` l'écrit et `check` refuse qu'il soit périmé.

**Tech Stack :** Next.js 16 (export statique), React 19.2.8, Tailwind v4, Node ≥ 20 (scripts ESM sans dépendance).

**Spec :** `docs/specs/2026-11-13-page-docs-design.md`. Lis-la avant de commencer : ce plan argumente à partir d'elle.

## Global Constraints

- Ne jamais modifier une copie du portfolio dans `site/`. On corrige dans `~/portfolio`, puis `node site/scripts/copy-from-portfolio.mjs`.
- Aucune dépendance nouvelle, ni à la racine ni dans `site/`.
- Ne jamais éditer à la main `packages/svg/dist/`, `packages/react/dist/`, `packages/svg/src/data.js`, `.github/assets/preview.svg` ni `site/public/neume-svg-24.zip` : `npm run build` les écrit.
- Contenu en anglais. Chaque phrase technique doit être vraie pour `@neume-icons/*` 0.2.0 : vérifie-la contre `packages/*/src` et `packages/*/README.md`.
- Mise en page de la doc :
  - une seule largeur pour le texte et les blocs, `--site-docs-copy-width: 48rem` ;
  - colonne centrée dans la page, rail du sommaire dans la marge gauche à partir de `xl` ;
  - `gap-32` entre sections, `gap-6` dans une section ;
  - `h2` en `font-pixel text-h2 font-normal`, `h3` en `font-pixel text-body-lg font-normal mt-6`.
- Tous les extraits de code passent par `CodeBlock` (multi-ligne depuis le portfolio `bfbc107`). Aucun `<pre>` brut.
- Commits en français, à la manière du dépôt (`feat(site): …`, `chore(site): …`, `docs: …`), terminés par la ligne `Co-Authored-By` de la session.
- On ne pousse pas sur `main` et on ne fusionne pas : un push sur `main` met en production. La PR est ouverte en brouillon.

## Review Focus

1. **Le zip ouvert pour de vrai.** `unzip -t` le déclare sain. Il contient 251 entrées nommées `<icône>.svg`, à plat, identiques aux fichiers de `packages/svg/dist/24/` (tâche 1, étape 5).
2. **L'accueil après l'extraction de la coque.** ⌘K ouvre la palette. Une recherche filtre le catalogue, et suivant / précédent dans la fiche suivent l'ordre filtré. La taille du curseur du catalogue est celle du SVG copié depuis la fiche (tâche 2, étape 4).
3. **375 px.** Un extrait long défile dans son bloc sans élargir la page, un tableau `Exhibit` tient dans la largeur, et la pastille du sommaire ne cache pas le pied de page (tâche 4, étape 6).
4. **Le thème sombre.** Les blocs de code, les tableaux, le cadre de la photo d'`AuthorLine`, les boutons icône et la scène des tailles restent lisibles (tâche 4, étape 6).
5. **Les ancres et le clavier.** `/docs#centring` arrive sous la barre, pas derrière. Tab parcourt le sommaire, les boutons de copie et les quatre boutons icône, qui ont un nom accessible et une bulle (tâche 4, étape 6).

- Dans `check.mjs`, la comparaison devient `Buffer.isBuffer(content) ? !readFileSync(f).equals(content) : readFileSync(f, "utf8") !== content`.
- `build.mjs` n'écrit que des chaînes : vérifie que `writeFileSync` reçoit le `Buffer` tel quel, sans conversion.
- Le message de fin de `build.mjs` cite aussi le zip.
